# 真实账号迁移验证（2026-11-26）

状态：真实 Linux 虚拟机中的免密码、免扫码导入、新消息正文接收、HaiA 显示及重启保留均已通过。修复纳入 HaiA 0.9.15。

## 环境与方法

- 源端：macOS / arm64，Electron 45.4.1；使用已有的真实 WhatsApp 登录资料。
- 目标：Docker Desktop 虚拟机中的独立 Linux / arm64 环境，同版本 Electron、真实 WhatsApp 网络。
- 没有注入模拟 provider，没有屏蔽或模拟 WhatsApp 网络，没有调用扫码、配对或关联码接口。
- 第一轮通过真实 `backupExport` / `backupImport` 路由复现故障。修复同步状态后，用生产 `authSnapshot`、Cookie 和归档模块从停止运行的源账号生成最终测试包，避免源端上线抢收正在测试的消息；目标通过真实 `backupImport` 路由导入。
- 最终包为 337,979 字节；不含消息记录、联系人和附件。必要的同步完成标志属于协议状态，并非聊天内容。
- 自测消息发送经用户明确授权。原消息发送失败后，调用 WhatsApp 原生重试，保留同一消息 ID；接收端只出现一条完全匹配的自测正文。
- 登录包、浏览器资料和原始诊断日志保存在仓库之外的私有目录，不提交到 Git。以下结论依据实际运行记录，单元测试不替代此验收。

0.9.15 发布复验：统一界面后的 39 项单元测试、完整桌面回归与重启检查通过；真实账号在 Linux 虚拟机中重新启动后，原自测正文仍能完整读取并显示。三个架构的安装包均已逐文件核对当前 117 个源码文件。

此结果验证新消息的真实接收及持久化，不代表仅登录资料能恢复主手机上的全部旧历史，也不代表已验证第二台实体 Windows 或 Mac。

## 定位与修复

1. 原 0.9.14 精简包缺少可跨系统恢复的登录 Cookie、设备注册字段。Cookie 现通过 Electron API 导入导出，避免搬运受源操作系统加密的 Cookie 数据库。
2. 只补登录字段仍出现“认证成功但没有正文”。源账号已有 `WAInitialHistorySynced=true` 等完成标志，精简导出却删掉这些状态；目标反复出现同步进度错误，无法正常处理消息。
3. 保留初始历史同步完成标志、状态及最后处理的同步块元数据后，目标无需重新关联便收到同一条待投递自测正文和其他真实入站正文。导出继续排除消息表、联系人表、附件和统计计数。
4. 测试工具增加真实 socket 状态、精确入站正文与 HaiA 应用状态双重核对、截图和正常关闭前的存储刷新。Linux 测试环境补齐中文字体，避免截图中的中文显示成方框。
